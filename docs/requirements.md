# ウマ娘 総獲得ファン数 日次集計ツール 要件定義(v1.1)

## 1. 目的
ウマ娘(PC版)のプロフィール画面「進行状況」のスクリーンショットから「総獲得ファン数」を読み取り、日ごとの推移と増加量をグラフで確認できるWebアプリを作る。

## 2. 確定した前提
| 項目 | 内容 |
|------|------|
| 対象画面 | プロフィール > 進行状況ダイアログ(下部「ファン / 総獲得数」行) |
| 実行環境 | PC版のスクショ(例: 1625×914 前後の JPG/PNG)。Windows 11 のローカルで動作 |
| 集計対象 | 自分1人のみ |
| 撮影頻度 | 1日1枚 |
| ファイル名形式 | `YYYYMMDDhhmmss_1.jpg`(例: `20261007204638_1.jpg`) |
| 日付の決定 | ファイル名先頭14桁から日付・時刻を取得。形式不一致ならファイル更新日時、さらに手動指定 |
| 同日の複数枚 | その日の中で最も新しい撮影時刻のファイルを**必ず**採用(他は破棄ではなく履歴として保持。採用の切り替えは行わない) |
| 日替わり | **ゲームの日替わりに合わせて AM 5:00 で区切る**(例: 10/8 04:59 の撮影は 10/7 分、10/8 05:00 は 10/8 分)。区切り時刻は設定値として定数化する |
| 利用形態 | ローカルWebアプリ(ブラウザで操作) |
| 出力 | グラフ(推移・日次増加量) |
| データ | ローカル保存のみ。外部送信なし。ゲームの自動操作・通信取得は行わない |

### 読み取り対象の仕様(サンプルより)
- 表記は `2,672,583,581人`(カンマ区切り、末尾「人」、約10桁)。
- 位置は進行状況ダイアログ内の最下部付近。
- v1 では**固定相対座標の切り出し**で読み取る(サンプル3枚はダイアログの位置・サイズが完全に同一のため)。ラベル検出による位置特定は v1 のスコープ外とし、レイアウトが変わった場合は切り出し座標の設定差し替えで対応する(NFR-4)。
- 画面の背景(右側のメニュー)はぼかされており、読み取り対象外。

## 3. 機能要件

### 3.1 画像取り込み
- FR-1: 画像(PNG/JPG)をブラウザでドラッグ&ドロップまたはファイル選択で取り込める。複数枚の一括取り込み可。
- FR-2: ファイル名 `YYYYMMDDhhmmss_*.jpg` から撮影日時を抽出し、取り込み時に集計日(AM 5:00 区切り)を表示・修正できる。
- FR-3: 同一画像(ハッシュ一致)は二重登録しない。同じ集計日に複数枚ある場合は撮影時刻が最新のものを必ず採用し、古いものは採用対象外として履歴に残す(取り込み順ではなく撮影時刻で判定)。履歴は記録一覧から参照できる。

### 3.2 数値の読み取り
- FR-4: 画像上の固定相対座標(画像サイズに対する割合)で「総獲得数」行の数値領域を切り出し、数字を読み取る。解像度が異なっても動作するよう相対座標を使う。切り出し座標は設定ファイルで差し替えられる。
- FR-5: 数値は整数(カンマと「人」を除去)として保存する。
- FR-6: 異常値を警告する。
  - 桁数が異常、または読み取り信頼度が低い。
  - 前回記録値より小さい(ファン数は単調増加のため)。
  - 日次増加量が過去実績から大きく外れている。判定は「直近14記録の日次増加量の中央値の3倍超(または1/3未満)」を既定とし、倍率・件数は設定ファイルで変更できる。有効な増加量が5件未満の間は判定しない。
- FR-7: 取り込み後、確認画面で読み取り値と元画像の該当部分を並べて表示し、利用者が修正・確定できる。

### 3.3 データ管理
- FR-8: 記録(集計日、撮影日時、総獲得ファン数、元画像ファイル名/ハッシュ、採用フラグ、手修正フラグ)を SQLite に保存する。
- FR-9: 記録の一覧表示、手動追加・編集・削除ができる。履歴(非採用)の記録も表示できる。
- FR-10: CSV エクスポート/インポートができる。文字コードは UTF-8 BOM 付き。インポート時に集計日が既存記録と重複する場合は、確認のうえ上書きまたはスキップを選べる。

### 3.4 集計・グラフ
- FR-11: 集計日ごとの総獲得ファン数と、前記録日との差(日次獲得ファン数)を表で表示する。
- FR-12: グラフ表示。
  - 折れ線: 総獲得ファン数の推移。
  - 棒: 日次増加量。
  - 期間切替(直近7日/30日/全期間)。
- FR-13: 週次・月次の合計、平均、最大の増加量を表示する。日割り補間オプションが有効な場合は、補間後の値で集計する。
- FR-14: 未撮影日は欠損として扱い、増加量は「経過日数分の合計」と注記する。日割り補間は表示オプションとし、有効にするとグラフ(FR-12)と週次・月次集計(FR-13)の両方に反映する。無効時は欠損のまま表示する。
- FR-15: グラフ画像(PNG)でダウンロードできる。

## 4. 非機能要件
- NFR-1: 読み取り精度は確認画面での修正を前提に、確定データは正確であること。通常の読み取りは10桁を誤りなく読むことを目標とする。
- NFR-2: 1枚の処理は数秒以内。
- NFR-3: 画像とデータはローカルのみで扱う。
- NFR-4: ゲームのアップデートでレイアウトが変わっても、切り出し座標の設定差し替えで対応できる。
- NFR-5: Windows 11 で `起動コマンド1つ` で使える(依存は最小限)。
- NFR-6: 読み取り失敗・警告はログに残す。

## 5. 技術方針(案)
- バックエンド: Python(FastAPI など)+ SQLite。
- OCR: 固定相対座標で数字領域を切り出し → 拡大・二値化 → 数字読み取り。フォントが固定のため、数字テンプレート照合を第一候補とする(Tesseract は Windows で別途インストールが必要で NFR-5 と相性が悪いため、使う場合は任意の代替手段とする)。PaddleOCR は依存が重いため採用しない。
- フロントエンド: 単一ページ(HTML + JS)、グラフは Chart.js(PNG 出力は `toBase64Image()`)。
- 元画像はローカルのデータフォルダにコピー保存する(確認画面の再表示と再読み取りのため)。
- 精度検証用に、サンプルスクショで正答を確認するテストを用意する。

## 6. 画面構成
1. 取り込み: ドロップ領域、読み取り結果と元画像の切り抜き、日付・数値の修正、確定。
2. ダッシュボード: 推移グラフ、日次増加グラフ、週次/月次サマリ、補間オプション。
3. 記録一覧: 表(採用・履歴)、編集・削除、CSV 入出力。

## 7. スコープ外
- ゲームの自動操作・通信解析、スクショの自動取得。
- 複数ユーザー、クラウド同期、スマホ版画面への最適化(必要なら後で追加)。
- ファン数以外の項目(育成回数、トロフィー数など)の読み取り。ただし同じダイアログに表示されるため、拡張しやすい設計にする。
- ラベル検出による読み取り位置の自動特定(v1 は固定相対座標のみ)。

## 8. 受け入れ基準
1. サンプルスクショ(総獲得数 2,672,583,581人)から正しい値が読み取れる。
2. 複数日分の画像を取り込むと、日次増加量が正しく計算され、グラフに表示される。
3. ファイル名から集計日(AM 5:00 区切り)が推測され、修正もできる。
4. 減少値・桁異常・欠損日が警告または明示される。
5. 同じ画像を再取り込みしても二重登録されない。
6. CSV エクスポートの内容が表示と一致する。
7. 同じ集計日の複数枚のうち、撮影時刻が最新のものが採用される。
8. 日割り補間を有効にすると、グラフと週次・月次集計の両方に反映される。

## 9. 確認済み事項
- ファイル名形式は `YYYYMMDDhhmmss_1.jpg`、同日複数枚は最新を必ず採用。
- 日替わりは AM 5:00(ゲームの日替わりに合わせる)。
- 読み取りは固定相対座標の切り出しで行う。
- 日割り補間は週次・月次集計にも反映する。
- 提供された3枚のサンプルは、ダイアログの位置・サイズが完全に同一(1625×914程度)。総獲得数の期待値は以下で、OCRテストの正解データに使う。
  - 2,672,583,581 / 2,658,611,645 / 2,654,906,664
- 背景メニューの赤バッジ有無など、ダイアログ外の差異は読み取りに影響しない。
